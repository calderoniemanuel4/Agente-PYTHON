01 / Objetivo

Aprender construyendo, no coleccionando servicios

Partimos de un backend real con FastAPI, Twilio, OpenAI y Google Sheets. La meta es evolucionarlo de forma incremental hacia una plataforma reutilizable de agentes y automatizaciones, sin migraciones prematuras.

Comprender

Tool calling, protocolos, recuperación documental, coordinación de agentes y arquitectura por eventos.

02

Experimentar

Laboratorios pequeños, reproducibles y versionados, con pruebas y criterios de aceptación.

03

Operar

Identidad, mínimos privilegios, aprobación humana, observabilidad, evaluación y control de costos.

Principio de diseño: un agente solo cuando aporta valor. Si un flujo se resuelve mejor con una función determinista, usar una función determinista. Codex ayuda a escribir y revisar el código; no sustituye la autorización de acciones de negocio.

Plano de ejecución

Entrada autenticada → reglas de negocio → selección de herramientas → ejecución → validación de resultados → respuesta o tarea pendiente de aprobación.

Agentes iniciales: documental (Drive/PDF), datos (Sheets/Firestore), operativo (webhooks) y analista (informes).

Plano de control

Identidad, permisos por herramienta, secretos, auditoría, trazas, métricas, datasets de evaluación, presupuestos y revisión humana.

Despliegue: local → Cloud Run existente → prueba comparativa opcional con AWS Bedrock AgentCore.

MCP estandariza la interacción con herramientas; AgentCore Gateway es una opción administrada para exponerlas y gestionarlas. No son sinónimos ni obligan a usar el mismo proveedor de modelos.
03 / Programa

Roadmap detallado · 10 semanas

Abrí cada módulo para ver objetivos, práctica, entregable y condiciones para avanzar.

01Semanas 1–2 · Responses API y herramientasDel prompt a una ejecución controlada＋

Aprender: roles y contexto, function calling, esquemas JSON, Pydantic, validación de argumentos, estados de ejecución, límites y errores.

Practicar: construir consultar_estado_pedido(id) con datos ficticios; el modelo propone la llamada y Python valida y ejecuta. Añadir una herramienta de escritura que exija confirmación.

Entregable: endpoint POST /agent/run y pruebas unitarias para entradas válidas, inválidas y no autorizadas.

Terminado cuando: no se ejecuta ninguna acción fuera de la lista permitida; se registran las llamadas sin filtrar secretos.

02Semana 3 · MCP y catálogo de toolsUna integración, varios consumidores＋

Aprender: cliente/servidor MCP, tools, resources, prompts, transporte, autenticación y diferencias frente a una API REST.

Practicar: exponer lectura de una hoja de prueba mediante un servidor MCP Python; limitar hojas, rangos y operaciones.

Entregable: servicio tools-sheets consumible desde un cliente de prueba.

Terminado cuando: un cliente autorizado puede consultar, pero no editar ni acceder a otras hojas.

03Semana 4 · RAG y retrieval agénticoRespuestas verificables sobre documentos＋

Aprender: parsing, chunking, embeddings, índices, búsqueda híbrida, reranking, reformulación, citas y abstención ante evidencia insuficiente.

Practicar: indexar un conjunto de PDFs no sensibles; responder con referencias al documento y página. Probar consultas ambiguas y sin respuesta.

Entregable: asistente documental con referencias y verificación de permisos al momento de responder.

Terminado cuando: el agente no inventa citas y rechaza documentos no autorizados.

04Semana 5 · Agentes especialistasOrquestación sin complejidad innecesaria＋

Aprender: delegación, handoffs, contexto compartido, memoria, presupuestos por tarea y prevención de bucles.

Practicar: separar un agente documental y otro de datos; un coordinador determina si hacen falta ambos.

Entregable: flujo de dos especialistas con trazas y límites de pasos.

Terminado cuando: se demuestra que el diseño multiagente supera al agente único en casos medidos, o se documenta por qué no conviene.

05Semana 6 · Eventos y automatizacionesDe responder mensajes a ejecutar procesos＋

Aprender: webhooks firmados, colas, idempotencia, reintentos con backoff, trabajos diferidos, dead-letter queues y aprobaciones.

Practicar: un webhook simulado recibe una notificación de documento, extrae metadatos y prepara una tarea para aprobación.

Entregable: pipeline con estado persistido y sin procesamiento duplicado.

Terminado cuando: repetir el evento no duplica acciones y los errores son recuperables.

06Semana 7 · Seguridad y gobiernoPermisos antes que autonomía＋

Aprender: OAuth, IAM, RBAC, mínimo privilegio, gestión de secretos, prompt injection, separación de datos y control de acciones de alto impacto.

Practicar: usuarios con permisos distintos; bloquear escritura sin autorización y sin aprobación.

Entregable: matriz de permisos, auditoría y pruebas negativas.

Terminado cuando: el acceso a una herramienta o documento no puede ampliarse mediante instrucciones en contenido externo.

07Semana 8 · Evaluación y observabilidadMedir calidad, no solo latencia＋

Aprender: golden datasets, exactitud de herramientas, fidelidad a fuentes, regresiones, trazas, costos y revisión humana.

Practicar: 30–50 casos representativos; comparar versiones de prompts y modelos, incluyendo entradas maliciosas.

Entregable: pruebas con pytest y reporte de métricas.

Terminado cuando: hay una línea base cuantitativa y un criterio de promoción entre versiones.

08Semana 9 · Bedrock AgentCoreComparar servicios administrados con nuestra base＋

Aprender: AgentCore Runtime, Gateway, Identity, observabilidad, registro y opciones de conexión.

Practicar: reproducir una tool de lectura con el servicio administrado, usando datos ficticios y límites de gasto.

Entregable: informe de comparación: costo, complejidad, seguridad, portabilidad, latencia y operación.

Terminado cuando: existe una decisión documentada de adoptar, postergar o descartar, basada en pruebas.

09Semana 10 · AgentHub v1Integración, despliegue y documentación＋

Aprender: integración continua, gestión de versiones, health checks, despliegues, rollback y runbooks.

Practicar: conectar canal, orquestador, una tool MCP, persistencia, permisos, trazas y pruebas de regresión.

Entregable: repositorio documentado, entorno reproducible y demostración extremo a extremo.

Terminado cuando: otra persona puede instalarlo, probarlo y comprender sus límites siguiendo el README.

05 / Calidad

Evaluaciones que convierten una demo en producto

MétricaQué respondeCómo medirla
Exactitud de herramienta¿Seleccionó la tool correcta?Comparar llamadas con casos esperados
Fidelidad documental¿La respuesta está respaldada por fuentes?Verificar citas y evidencia
Acciones autorizadas¿Respetó permisos y aprobaciones?Pruebas negativas y logs
Éxito extremo a extremo¿Completó la tarea?Casos de aceptación
Latencia p95¿Responde con velocidad aceptable?Trazas y percentiles
Costo por tarea¿Es sostenible?Tokens, herramientas e infraestructura

Definir umbrales después de medir una línea base. No fijar porcentajes arbitrarios ni confundir respuestas plausibles con resultados correctos.

06 / Operación responsable

Checklist mínimo de producción

Antes de ejecutar

  • Autenticar solicitante y origen del evento.
  • Validar entradas con esquemas.
  • Limitar herramientas por usuario y contexto.
  • Separar instrucciones de documentos no confiables.

Durante la ejecución

  • Aplicar timeouts y presupuestos.
  • Registrar trazas sin secretos ni datos innecesarios.
  • Usar idempotencia en operaciones repetibles.
  • Exigir aprobación para cambios sensibles.

Después de ejecutar

  • Verificar el efecto real de la acción.
  • Guardar auditoría y resultado.
  • Medir fallas y regresiones.
  • Preparar reversión y recuperación.
